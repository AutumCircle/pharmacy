# Product image storage proposal (not deployed)

The current carousel implementation stores only validated HTTPS image metadata
in PostgreSQL. No AWS storage resource was created because the AWS CLI session
available to this workspace has no configured credentials/profile.

If the account has no suitable existing image bucket/CDN, use:

- a private S3 bucket in `eu-central-1` with Block Public Access enabled;
- CloudFront with Origin Access Control for public reads;
- an Admin Lambda operation that creates a restricted presigned POST/PUT;
- collision-resistant keys generated by Lambda, for example
  `products/{medicine_id}/{uuid4}.webp` (never use the browser filename);
- allowed MIME types: `image/jpeg`, `image/png`, `image/webp`;
- maximum object size: 5 MB, enforced in the signed upload policy;
- bucket CORS restricted to the final admin-panel origin;
- lifecycle cleanup for abandoned temporary uploads.

The browser receives a short-lived upload URL, never AWS credentials. After a
successful upload, Next.js sends the resulting HTTPS CDN URL through the Admin
API; Lambda validates it and writes `medicines.image_url` in RDS.

Suggested server-only environment-variable names:

- `PRODUCT_IMAGE_BUCKET`
- `PRODUCT_IMAGE_REGION`
- `PRODUCT_IMAGE_CDN_BASE_URL`
- `PRODUCT_IMAGE_MAX_BYTES`

Before implementation, inspect and reuse any existing S3 bucket, CloudFront
distribution, IAM policy, and domain rather than creating duplicates.
