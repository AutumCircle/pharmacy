# Отдельный мобильный баннер — порядок публикации

Изменения пока не применены к AWS. Не публиковать только frontend:
старый backend не принимает слот `mobile`.

1. Собрать пакеты штатным `scripts/build_lambda_packages.py`.
2. Развернуть пакет `migration-0011-mobile-banner-once.zip` как отдельную
   одноразовую Lambda с существующими настройками доступа к RDS и psycopg2.
   Не заменять рабочий обработчик API миграционным обработчиком.
3. Выполнить `action: inspect`, затем при согласованном выпуске `action: apply`
   с `confirmation: VATAN-0011-MOBILE-BANNER`. Миграция транзакционная,
   повторяемая, не изменяет четыре существующих баннера.
4. Обновить admin-api-v1 пакетом из этой сборки; public-api уже читает все
   активные слоты, дополнительной миграции данных не нужно.
5. Опубликовать frontend. Загрузить отдельную мобильную фотографию в
   `/admin/banners/mobile`, проверить предпросмотр и включить баннер.
   До включения мобильный блок скрыт, desktop-картинки его не заменяют.
6. Проверить сохранение без заголовка, телефон 390px и desktop 1440px,
   отсутствие обрезки и совпадение текста в редакторе и на главной.

Размеры: left 1000×1400, center 1500×1000, right 1600×900,
mobile 1200×600. При загрузке выполняется пропорциональное вписывание
на белый холст точного размера. Старые изображения не перезаписываются.
