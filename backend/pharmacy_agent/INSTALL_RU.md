# Установка агента Oracle на компьютер аптеки

Агент `pharmacy_agent.exe` читает из Oracle «Алгоритма» товары, остатки, партии и справочники
и отправляет их на сервер сайта. Он **только читает** базу и работает параллельно со старым
`agent_sync.exe`, OraExchange и выгрузкой на FTP — их не трогаем.

## Что нужно заранее

| Что | Где взять |
| --- | --- |
| Архив `pharmacy-agent-win7-py38.zip` | Собирается скриптом `scripts/build_pharmacy_agent.ps1` |
| Адрес API (`api_base_url`) и ключ аптеки (`api_token`) | Выдаёт администратор сайта. Ключ для каждой аптеки свой |
| Пароль пользователя `SYSTEM` в Oracle | Нужен один раз, чтобы создать пользователя только для чтения |

## Шаг 1. Пользователь Oracle только для чтения (один раз)

1. Скопируйте `create_site_reader.sql` в `D:\VatanAgent\`.
2. В CMD:
   ```
   cd /d D:\VatanAgent
   sqlplus SYSTEM@127.0.0.1:1521/xe @create_site_reader.sql
   ```
3. Введите пароль `SYSTEM`, затем придумайте пароль для `SITE_READER`.
4. В конце должно быть `GRANTED_TABLES = 12`.

Скрипт создаёт нового пользователя и даёт ему **только чтение** 12 таблиц. Таблицы «Алгоритма»
он не меняет. Пароль `ORGANIZ` не меняется.

## Шаг 2. Файлы агента

1. Распакуйте архив в `D:\VatanAgent\`.
2. Скопируйте `config.example.json` в `config.json` и заполните:
   - `pharmacy_id` — `1`;
   - `api_base_url`, `api_token`, при необходимости `api_gateway_key`;
   - `oracle.password` — пароль `SITE_READER` из шага 1;
   - `oracle.client_lib_dir` — папка, где лежит `oci.dll`. Обычно
     `C:\oraclexe\app\oracle\product\11.2.0\server\bin`. Проверьте, что файл там есть.
3. `config.json` содержит пароли: не отправляйте его в чаты и не кладите в общие папки.

## Шаг 3. Пробный запуск

```
cd /d D:\VatanAgent
pharmacy_agent.exe --once
```

Первый запуск отправляет все таблицы целиком (около 900 тысяч строк). Это может занять
от 15 до 60 минут, в зависимости от интернета. Ход работы виден в `pharmacy_agent.log`.
Повторные запуски отправляют только изменения и длятся секунды.

Если в журнале `ORA-01017` — неверный пароль `SITE_READER`. `ORA-00942` — не выдан доступ
к таблице (повторите шаг 1). `DPI-1047` — неверный `client_lib_dir`.

## Шаг 4. Автозапуск через Планировщик заданий

Запустите `install_task.bat` **от имени администратора** (правый клик → «Запуск от имени
администратора»). Он создаёт две задачи:

| Задача | Когда | Зачем |
| --- | --- | --- |
| `VatanPharmacyAgent` | При включении компьютера | Основной запуск утром |
| `VatanPharmacyAgentWatchdog` | Каждые 5 минут | Перезапуск, если агент упал. Вторая копия сразу закрывается |

## Как работает в течение дня (07:30–01:00)

| Когда | Что отправляется |
| --- | --- |
| При включении утром | Полная сверка всех таблиц: изменения за ночь и удалённые строки |
| Каждую минуту | Изменившиеся остатки (`T_SKLAD_STATE`), товары (`T_PRODUCT`), новые партии (`T_INCOME`) |
| Каждые 5–10 минут | Изменения в справочниках |
| Каждые 15 минут | Полная сверка остатков — находит удалённые партии |
| Каждые 2–6 часов | Полная сверка остальных таблиц |

Если пропал интернет, агент ничего не теряет: в следующем цикле он сам досылает всё, что
сервер ещё не принял.

## Проверка и остановка

- Журнал: `D:\VatanAgent\pharmacy_agent.log`.
- Остановить: Диспетчер задач → `pharmacy_agent.exe` → «Завершить процесс». Чтобы агент не
  запускался снова — отключите обе задачи в Планировщике.
- Удалить локальное состояние (`pharmacy_agent_state.sqlite3`) можно только при остановленном
  агенте; после этого он заново отправит все таблицы.
