# Цены и поля карточки теневого зеркала

Обновление 22 октября 2026 к интерфейсу `/admin/pharmacy-mirror`.

В поиске ID явно подписан PRODUCT_ID: это исходный ID товара в «Алгоритме»,
проверенный в первой публикации на всём T_PRODUCT. ID партии — INCOME_ID,
ID строки остатков — SKLAD_STATE_ID, ID документа прихода — INCOME_HEAD_ID.

В результатах поиска и карточке теперь видны:

- Цена продажи за единицу: `T_SKLAD_STATE.OUTCOME_PRICE_ONE_W_NDS`, уровень 1, с НДС.
- Цена прихода за единицу: `T_INCOME.INCOME_PRICE_W_NDS`, с НДС.
- Диапазон цен партий с положительным PRODUCT_COUNT_SKLAD. Если таких партий нет,
  показаны цены исторических партий с соответствующей пометкой.
- Количество в наличии и стоимость текущего остатка по продаже / по приходу.
  Каждая стоимость — SUM(количество партии × её цена); резерв не вычитается.
  Это стоимость оставшихся товаров, не выручка и не сумма документов прихода.
- Если у ненулевой партии нет соответствующей цены или количество некорректно,
  итоговая стоимость NULL («Нет данных»). При нулевом количестве стоимость — 0.
- «Нет данных об остатке в зеркале» вместо «Нет строк остатков».

Цена прихода берётся только по точной связи INCOME_ID + PRODUCT_ID + pharmacy_id.
Никакого сопоставления по названию, изменения Oracle, зеркала или medicines.
Все агрегаты выполняются в одном SQL на стороне Lambda, только для 25 товаров
текущей страницы. Для приходов используется существующий PK; миграций не требуется.

Карточка содержит сводку цен/остатков и все полученные безопасные поля товара,
остатков и приходов в таблицах с русскими подписями и исходными ключами.
Расширен положительный список полей прихода: суммы, НДС, цены поставщика и внешнего
прихода. EMPLOY_ID и EXT_PARTNER_ID не возвращаются. NULL-поля Oracle агент не
передаёт. Назначение INCOME_DATE_OLD сохранено под исходным именем.

Контракт трёх GET endpoints сохранён; в stock/items добавлены:
`sale_price_min/max`, `purchase_price_min/max`, `sale_value`, `purchase_value`,
`price_basis=in_stock|historical|none`. У строки остатка дополнительно
`purchase_price` и `income_barcode`. Авторизация и no-store сохранены.

Проверки: 32 целевых Python test, 5 frontend tests зеркала, 198 существующих
frontend tests, Python compile. Дополнительно реальный PostgreSQL read-only SELECT
с синтетическими VALUES проверил дробные количества, разный диапазон цен,
нулевые исторические партии, отсутствующие цены, чужой PRODUCT_ID прихода и
некорректное количество. В RDS не создавались тестовые строки/таблицы.
