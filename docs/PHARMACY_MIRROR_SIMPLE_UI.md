# Простой интерфейс зеркала и пояснения «?»

23 октября 2026. Изменения для владельца аптеки:

- Поиск: товар, штрихкод, остаток, цена продажи и цена прихода за единицу.
  Стоимость всего остатка убрана из результатов и доступна внутри карточки.
- Карточка: главное, сведения о товаре, из чего складывается остаток.
  Стоимость остатка, история и все исходные поля свёрнуты по умолчанию.
- Вместо непонятного «Склад · Партия 143665» в основной строке показаны
  количество, название склада и две цены. Внутренний номер поступления доступен
  после раскрытия и снабжён пояснением.
- У остатков, цен, номеров, дат, синхронизации, сумм и исходных полей есть «?».
  Кнопка открывает диалог с простым объяснением и примерами. Доступны Enter/Space,
  Tab, Escape, «Понятно», крестик и закрытие нажатием на фон. Используется native
  modal dialog с focus trap и возвратом фокуса; портал не обрезается таблицей.
- Пояснения различают цену единицы и стоимость остатка, PRODUCT_ID/INCOME_ID,
  отсутствие данных и ноль, время получения в AWS и дату поступления/продажи.
  INCOME_DATE_OLD не выдаётся за подтверждённую дату или срок годности.

Для точного списка текущих поступлений добавлен read-only параметр detail
`stock_view=nonzero|all`. Фильтрация выполняется до LIMIT/OFFSET в Lambda.
Отрицательные и некорректные количества остаются видимыми; скрываются только
нулевые строки. Общий остаток и стоимость рассчитаны по всем строкам.
API default all сохраняет старое поведение; новый Next server layer запрашивает
nonzero. Stock/current metadata дополнены current_stock_rows. Schema/DDL и
синхронизация не менялись. На контрольном товаре проверены 3 текущие и 22 полные
записи. Все запросы параметризованы и исполняются в read-only transaction.

Файлы: `Help.tsx`, `pharmacy-mirror-help.ts`, страницы и `parts.tsx`/`mirror.css`
раздела pharmacy-mirror; серверный клиент, runtime types; точечная доработка
`pharmacy_mirror_admin.py`. В прочие admin/order/catalog handlers изменений нет.

Проверки: 34 целевых Python test, 6 tests зеркала и 198 прежних frontend tests.
Реальные response contracts nonzero/all проверены. Браузерные проверки включают
диалоги, управление клавиатурой и фокусом, пагинацию, переключение текущих/всех
поступлений, раскрытие исходных полей и отсутствие overflow на 390/320 px.
Сценарии проверки используют только GET/HEAD и не создают продажи или заказы.
